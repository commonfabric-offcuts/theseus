# Frozen pending reply destination

A submission freezes sourceRef separately from its writing snapshot.
Message-origin replies normally have no snapshot.reply_to: Core derives their
reply from source_ref. The local pending card uses that same frozen message
source when an explicit snapshot.reply_to is absent. Topic/Notebook sources
remain root sends. Later Reader/editor state cannot retarget a submission.

Both the dossier-container lookup and reply-context metadata use that effective
destination. Canonical maps, receipt admission, image ownership, confirmation
actions and later writing remain with their existing owners.

Interaction coverage: actual direct Reader and card-to-Reader ordinary send,
including unresolved publication, refused/unknown outcome and failed local
keep, use real Editor/Session/Registry/journal submissions without reply_to.
The pending card belongs after later canonical siblings in the dossier, before
New/composer. Preparing/prepared/confirmed rendering, explicit reply override,
topic/Notebook roots and later source changes have separate controls. Existing
pointer/key, focus/image and both arrival-order cases remain. Model controls
do not establish native geometry or the owner of Tony's screenshot gap.

The bounded window draws gap navigation after #messages, with no top spacer.
Existing holdRoom can add temporary list padding when retaining a card moved
across the page. Correct initial destination avoids the reproduced root-to-
dossier trip; screenshot-only gap attribution remains unproved.
