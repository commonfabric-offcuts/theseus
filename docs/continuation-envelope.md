# Original partial plus scoped completion

Only an explicit `source.continuation: Ref` selects this envelope. The ordinary
complete-source validator, required 52-step inventory, controller publication,
App identity, resolution review and own-case obligations retain their guards.
Unknown shapes refuse; there is no fallback. This is evidence consumption only.

The continuation dispatch and controller call require explicit `merged_context`,
just like complete-source validation. Direct unmerged callers pass `None`.
Postmerge callers carry the actual context authenticated by train/base-move
validation after its immutable source/assembly/release parent and tree checks.
An empty check association requires that context; forwarding never substitutes
`None` or supplies an optional default. Nonempty associations retain their exact
original binding. The module is closed deploy-owned code in both
`train.DEPLOY_TOOL` and Core's `DEPLOY_OWN` (warp8564/8583).

The continuation document is exactly `{version: 1, authorization, original,
completion}`. Authorization is a Ref to exactly `{reviewer, record, source_head,
source_tree, original_run, original_attempt, base_at_run, pr, original_workflow,
workflow_head, workflow, plan}`. Workflow Refs contain the exact frozen workflow
bytes read from the original tested merge and authorized manual workflow head.
The latter must be a child of the source, changing only checks.yml. Independent
review must authenticate the named authority and read both workflows: the
original command and plan, manual-only trigger, input checkout, source binding,
missing-only matrix, unfiltered modes and artifact publication. Merely naming
an arbitrary workflow_dispatch is insufficient. Authorization's record must
be distinct from the judgment audit; final resolution review binds all bytes.

Original and completion are exactly `{run, attempt, archives}`; completion also
has `workflow_head`. Each archive is exactly `{id, name, job, archive: Ref}`.
Original includes release-check (job null) and every planned check-N shard.
Completion includes exactly one check-N per authorized missing-only assignment.
Fresh GitHub GETs authenticate run, attempt, repository, workflow, PR/base/head,
jobs, artifact digest and artifact creation between that attempt's upload start
and job completion. GitHub can timestamp finalized artifacts one second after
the upload step's second-resolution end; no unbounded tolerance is used.
Duplicate ZIP names and unsafe paths refuse. Only digest-authenticated original
ZIP bytes count; no locally repackaged or rewritten source archive counts.

Original provenance and plan remain authoritative. Complete original shards
keep exact assignment and summary digest, clean ending, tool and harness OIDs.
Completion shards require the same complete-source proof, at their recorded
checked source rather than their workflow API head. For these authenticated
complete shards, runtime hashes and step-local source archives are optional:
absent measurements/files stay absent. Every actual `hashes` and `sourceHashes`
claim is validated against exact source and equal tested-tree bytes. A present
map must be nonempty and well formed; unsafe paths, malformed digests,
conflicting claims (including between spellings) and wrong source refuse.
Neither spelling overrides or hides the other. No other mode's archive is used.

A cut native shard has no summary and a null summary digest. Its completed
prefix comes from the authenticated original aggregate's recovered job-log
records, bound to the original job and assignment. Each completed mode must
have its whole raw reviewed case inventory, normal browser/fixture cleanup,
ordered log, nonempty source hashes and archived source bytes matching Git at
both source and tested merge. No whole-shard clean-tree certificate is inferred.
Both hash spellings are recognized under this stricter prefix proof too; every
claimed file needs its own step-local exact archive member. A complete-shard
exception is selected only after its existing clean summary/provenance checks.
No incomplete unit/replay partition is admitted.

Python file partitions are the sole deduplication authority: complete indexed
partitions, disjoint files and disjoint raw case identities must cover the
independently reviewed full Python inventory exactly once. Partition metadata
and original plan files agree. No other duplicate step is allowed. Aggregate
raw counts/exit/pass must agree with all original executions; no original red
may be removed. No summary is rewritten or fabricated.

Completion's workflow API head is distinct from its checked source. Every
dispatch-source.json binds the exact original source/tree/parents/base/run and
attempt, manual workflow head/ref and its own run/attempt. The receipt and
complete scoped summary agree; every selected mode runs whole. Original source
and tested merge trees must agree. Original completed modes retain their
original shard; continuation assignments equal exactly the missing set, with
no overlap, duplicates, extras, omissions or reassignment against authorization.

The result is labeled `original-partial-plus-scoped-completion`, with original
partial shard names, per-step placement and both original conclusions. It is
never a synthetic full-run summary or a green replacement for the original.
The existing source audit adds `continuation_sha256` and retains the original
summary digest; it must place every raw red across both runs exactly once.
Pending/cancelled/missing continuation evidence refuses concretely. Complete
coverage alone does not clear attribution or own-case proof. In particular this
envelope cannot fill item 717's WebKit ownTab or Chromium mutant/restore gaps,
and makes no change to the own receipt adapter. Those remain a separate scope
boundary, with independent placement/ruling retained by the coordinator.
