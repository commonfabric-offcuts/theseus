# Delete and Undo a Notebook page

1051, based on release324, commit4bc9e662c54f56bbb682450db217f256d7e51422.

Delete has no confirmation dialog. NotebookPage first captures its real visible writing through NotebookWriting; unsaved/conflicted writing or unavailable durable storage keeps the page open with its existing recovery. After the exact revision-fenced memory.delete deleted:true envelope and Undo target are durably kept together in the existing per-page journal, the sheet closes or the full page goes to its existing owner topic/outcome without reopening the deleted page. A close is acknowledgement of a kept request, not proof of deletion.

A quiet notice below the page header provides Undo on phones and desktops. Confirmed deletion offers Undo for ten minutes from its receipt; the target survives navigation and reload within that interval. Unconfirmed deletion/restoration never expires: it says confirmation is unknown and offers Retry. Only Core's matching recorded receipt decides committed/rejected; retry retains the exact operation identity. A definite refusal says so and offers to reopen the page, without claiming success. History remains in Core after the notice expires.

Command-Z outside editable writing and browser beforeinput historyUndo when supplied use the same most recent available Notebook deletion as the notice. Text editing keeps its own native Undo. An Undo requested during an unconfirmed delete is journaled; it waits for that exact delete's receipt before creating a new memory.delete deleted:false against the confirmed deletion revision. Restore confirmation reopens the same page; a lost restore response retries its original identity. A refused restore leaves an explicit error and an Open page door. A later revision/authority is never silently borrowed to replay a refused action.

NotebookWriting remains the sole save/action owner, with its current CAS, access checks, Web Lock and image/writing recovery. A scope index in that same IndexedDB database discovers only recent/pending deletion journals for this instance/person; it is a cache/pointer, never independent record authority. Pending requests are recovered through NotebookWriting. A full-page departure releases its per-page Web Lock after journaling, before navigating; the destination resumes that exact request. Sheet departure retires DOM listeners while its retained action writer finishes; subsequent page openings hand off that same per-page ownership before acquiring its lock. No Core command or schema changes.

Proof includes actual baseline dialog/page-stays, native menu delete/close/Command-Z/phone Undo, same-page reopen, reload and Core history, unconfirmed/rejected writes and exact retries, meaningful applied fault/exact restore, and full paired existing-owner diagnostics. Synthetic historyUndo covers routing only; it does not prove an OS Edit menu gesture. Browser runs use isolated headless Chrome for Testing and installed WebKit with scratch fixture records and verified Browser.close/profile/PID/fixture cleanup. No physical device/OS-menu claim.

Device storage upgrades from v2 to v3, preserving the existing writing/images stores and adding the atomic deletion index. An older tab holding v2 must close before upgrade; a blocked upgrade says to close older Notebook tabs and reload rather than leaving startup pending. New connections close on version change. Discovery reads twenty recent indexed metadata records per page; Older Notebook changes continues that index. Unresolved records remain kept even beyond the current page of notices. Expired confirmed targets are cleared when resumed on a new document; Core history is unaffected.
