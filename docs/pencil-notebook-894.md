# Notebook pages from the pencil sheet (894)

Item 910 replaces the three choices with Message | Note in one radio group. Note is the default on each sheet opening and on returning to the composer at rest. The choices are offered in both places when the topic Notebook read says reader_may_write === true; otherwise Message remains available. The pill occupies a full centered grid row and matches the Everyone here chip height and corner radius. The sheet title remains an accessible label but is not drawn. Switching keeps the expanded sheet, chosen radio focus, writing and caret; arrow keys select and focus the next choice. Message sending is unchanged.

Note (the former Note card) creates a new page in this topic, using textCard’s first nonblank line as its title (heading marks removed, CRLF normalized) and its remaining words, serialized through the existing card writer. A blank title becomes Notebook page. It addresses and notifies nobody, creates a new page, and never appends to an existing one. The action reads Start page. Message recipients, intent and image controls are hidden and unavailable in either Notebook mode; retained message attachments and recipients stay with the message draft. Returning to Message restores its Message action label (Send, Ask or Whisper), recipient and intent controls, and visible image strip. Message-only image preparation does not block a page with no attachments; writing recovery and access barriers still do.

NotebookStart in quick-create.mjs remains the sole memory.create envelope and confirmation owner used by the rail pencil and this sheet. It accepts an initial body and retains title, body, scope and operation identity together through uncertain answers. A changed writing starts a distinct request, while each earlier uncertain request keeps its exact envelope and an explicit Retry earlier page action. A confirmed earlier result has its own Open started page action; it never takes over Start page for new writing. Retrying the same writing and kind retains the operation identity. The composer keeps each result until it is opened, so a late confirmation cannot create a second page on retry. While creating, writing and submission are disabled. Refusal retains the writing and shows the original error, including after closing and reopening the same editor. NotebookStart owns the appropriate retry wording for its caller.

A confirmation clears only the exact submitted writing through the existing editor and save callback. A later version, cycle, presentation or composer opening is never cleared or dismissed. Starting in the inline composer opens the confirmed page too; opening or closing the sheet while it is pending makes it an earlier result that must be opened explicitly. A late result offers Open started page. Opening goes through openNotebook with an explicit view and beside request: dock beside the current feed when possible, otherwise use the full Notebook route. Cards starts with the first card picked; Text opens the body. The beside request applies to that opening and its resizes; it does not change the saved Side by side preference or a later ordinary opening. An explicit layout choice still changes the preference. Existing rail and ordinary Notebook openings retain their behavior.

Owners: InlineComposer owns the segmented controls and current presentation, WritingInput/editor/registry own writing and recovery, NotebookStart owns creation identity and result validation, deckBody owns card serialization, openNotebook/NotebookSheet/NotebookPage own navigation, layout and selection. No new command, store, notification path or retry scheduler is introduced.

Focused tests use actual owners with in-memory command and DOM adapters. They cover mode switching, requests and radio keys, refusal and exact retry, late results/newer writing, dock/full-page opening and the unchanged message path. These are not native phone or screen-reader evidence. Item 910 also has an isolated browser check in tests/pencil_pill_910_native.mjs using the actual index, styles, Editor and InlineComposer: inline and sheet at 320, 390 and 1280 pixels in light and dark appearances. It measures matching chip height/radius and centering, checks the accessible title and two-choice keyboard behavior, and preserves exact writing and selection. It uses fixture callbacks, not a live account or real-device keyboard.

Build 2 replaces the old composer check that required restoring earlier writing before any new start. That restriction is deliberately retired; NotebookStart still refuses changing the payload of one pending request. New checks mount the actual radio and message controls inside the composer root and exercise its real fold/focus and image admission owners. Focus, layout rules and DOM tests are bounded source/adapter evidence, not native phone evidence.

On phones (760px and under), the To and + panels occupy their own named row below the writing and Send, in both ordinary and Retry layouts. The pencil keeps its separate desktop panel placement. Build 3 checks resolve the phone panel row against both templates and exercise working upload reservations, false/absent write capability, and a Note-page input event; these remain source/adapter checks, not native geometry evidence.
