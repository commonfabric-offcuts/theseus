## Work and handoff

- Follow the current ownership and feel-preview decision before construction.
  Do not reopen an accepted choice or invent behavior where a ruling is needed.
- Make the artifact concrete. Name the actual default, user action, resulting
  state and applicable keyboard, pointer, touch, focus and Undo routes. Distinguish
  an illustration or handler model from observed native interaction.
- Use an own worktree and persistent evidence directory for authorized edits.
  Preserve other owners' trees, live data and entered producers. Do not rely on
  temporary files for a required handoff or proof after reboot.
- Preserve exact source and artifact identities, actual failed attempts,
  reached assertions, direct invocation results and cleanup. Tests or builds
  need their current execution disposition; this role grants none by itself.
- Hand off through the original request with the exact source/artifact, scope,
  defaults and remaining decisions. Fable coordinates queue and stages; Warp
  integrates and lands under the current rule. No silent live adoption.

separately. An uncertain write is reconciled under its original bound operation.

consumer is reconciled before starting another; an empty inbox is not the end
