# Ask for a first cover (840)

A loaded original dossier with no cover offers “Ask for a cover”: a cover-plus
glyph before Reply, Archive and More, and the same act in its dossier menu.
The title bar uses its existing hover, focus and touch visibility rules. Its
reserved width includes the new control only while that control exists.
Existing covers retain their refresh control; a reply standing in for an
unloaded original offers no first-cover act.

Both doors use the existing `stack.cover_refresh` command, empty args, root
message id, observed cover revision and captured authority. Core now accepts
an absent cover at that revision. The recipient default remains the recorded
eligible agent writer, otherwise the outcome's explicitly configured eligible
coordinator. No inferred author, arbitrary team member or new access grant.
The first-cover request asks for a cover from the dossier's actual facts.

The existing durable request owns publication, coalescing, exact-operation
retry and completion. An initial request at cover revision zero does not
manufacture a cover in message or dossier projections. Waiting dots remain in
the title bar with a link to the request until a cover arrives. A previously
cleared cover keeps the existing refresh projection and request semantics.
Only a changed, nonempty agent cover write completes the request; replies,
acknowledgements, no-op writes, empty writes and human writes do not.

The page shares the existing refresh owner, including durable unconfirmed
envelopes, authority fencing and honest errors. “Asked <recipient> to write a
cover” is accessible text and a tooltip only. Waiting dots are the only visible
progress; errors stay visible (Warp11616). No visible progress sentence.

Pending or busy title activity stays visible after hover ends; the other title
tools keep their existing visibility rule (Warp11706). Opacity and clipping
belong to each tool so the activity can stay visible independently. A pending
menu item says “Open the cover request” and follows the same link as the dots.

Checks use isolated real Core records and actual page renderers/handlers.
Applied mutations must fail and restore exactly. No schema change is expected;
no browser, native gesture, geometry or full-suite claim is made.
