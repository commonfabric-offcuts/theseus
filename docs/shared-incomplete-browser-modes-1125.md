A non-completing candidate mode may have its failure to reach the end
excluded only when EVERY selected authenticated base record ends in the
same state: the same completion value (including an absent attestation),
the same actual case count, and the same body error or its absence.
An empty selection, a completed base, mixed history or a different end
state cannot establish this exception. The rule applies to every native
mode; it is not keyed to header, card-marks or a specific posting error.

Only the incompleteness is excluded and disclosed. Every reached case
continues through the ordinary known-red/new-red, identity, source,
profile and fingerprint comparison. No mode or reached red is turned
into a synthetic pass or quarantine. A candidate that reaches its end
on a truncated base is judged normally. The1124 all-zero rule remains
separate and retains its existing scope.

All raw counts, errors, direct exits, source/receipt bindings and owned
browser/fixture cleanup remain validated. Absence of a completion mark
is not absence of a report, and missing or malformed evidence is never
invented as a matching state. Preserve raw artifacts and earlier refusals.
Disclose the candidate state and all selected base run identities/states.

Warp requires the same bounded procedure as1124: ordinary positive and
negative judge units, one bounded run, exact source/output for independent
auditor review, then reviewed controller delivery and its actual SHA.
No broad suite, browser launch or production mutation campaign is scheduled.
After controller delivery, the separately authorized five-source drop and
restore precedes Warp's fresh carry/commit; never rerun the old producer.

## Implemented comparison

The comparison retains present bodyCompleted/harnessCompleted booleans,
present bodyError/harnessError values (including null), actual results length,
the end assertion and any planned/completed phase lists. Absent fields remain
absent. Existing completed formats and validated terminal fixture assertions
remain ordinary results; grouped compose cannot qualify from a missing state.
Nonempty incomplete records require successful browser/fixture cleanup,
including compose's short fixture and a valid completed-phase prefix.

Raw errors remain in the disclosure. The equality key uses the existing
normalize function: verified checkout paths and generated m-/t-/p-/d- IDs
receive stable labels. Each error must occur in the retained log, bodyError
also matches body-error.txt, and fingerprint verifies its source frames at
that record's commit. No arbitrary text or source frame is removed.

The history reader validates each selected record before constructing an
exception. The candidate must match every selected state. The result names
shared-incomplete with excluded=completion-only and includes all selected
run identities/states plus the candidate observations. Reached failures stay
in ordinary comparison. A completed candidate receives no such exclusion.
