# Loaded cover protection (1278)

A connected cover in the current message list protects its current displayed
stack head while any part of the cover is in the viewport, it contains the
active element, or a noncollapsed selection intersects it. The existing
window planner reserves that admitted head and its current dossier original;
a supplemental original reserves one admitted member. No historical member
list or persistent pin is added. Current stack membership, rather than a
cover's old source/root attribute, determines the protected identity.

The same300-record/8-run limits, external Reader/editor accounting, other
pins, admission pressure and ordinary arrivals apply. Hidden/disconnected
covers and sections outside this list add no pins. Once visibility, focus and
selection end, ordinary eviction and bounded gap/linked return apply.
No new data read, access change or timer is introduced.

Interactions: passive arrivals/cover refresh while reading a cover; pointer
or touch scroll bringing it into or out of view; keyboard focus on existing
cover controls; pointer/key text selection; and release of focus/selection.
The own complete Node file names these modeled paths and current membership,
retirement, privacy/writing, supplemental roots and cap controls. Native
pointer, touch, keyboard, layout and timing acceptance remain separate.
