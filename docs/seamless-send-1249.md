# A submitted card becomes its confirmed card (1249)

The exact frozen submission is a local presentation, outside TopicViews and
messageEntries. It has no speculative message id, sequence, unread state or
reactions. It uses ordinary card author/word/reply/image renderers, with an
honest quiet pending mark. Topic writing rests before the bottom composer;
reply writing rests immediately under its actual reply parent.
Multiple root submissions share an ordered end cursor. An unchanged group
is left in place, preserving its existing focused links and controls.

Only a validated committed send plus the matching authorized canonical page
permits adoption. The canonical painter binds that existing outer card to
the real id and sequence. The server's body, author, relationships and files
win. Equal content keeps its word/image nodes; changed content is repainted
under the existing reading anchor. Confirmation never creates a second local
copy or writes speculative records to the authoritative map.

Unknown/refused submissions, Check confirmation and unchanged-successor
restoration stay with the existing editor/session owners. Image previews use
the original submission's frozen selection links and binding, never the
successor's selection. A retired topic/access/authority cannot adopt or publish
late bytes. Disposal releases the local visual resources, not journaled work.

Pointer/key inline replies, the bottom pencil and Reader share this owner.
Focused controls cover contents, position/node/focus identity, canonical
differences, refusal/unknown/later writing/images and authority/topic fences.
Native layout shift, scroll motion, pixels and send timing remain separate
Flex observations after focused shipping under rule9.

When the page arrives before the receipt, the canonical card already owns its
normal interactions. Once the exact receipt arrives, that card replaces the
local presentation at its position; a focused matching link or the card keeps
focus. This path keeps the canonical binding instead of rebinding a second
card. When the receipt arrives first, the canonical painter adopts the local
outer card directly. Identical words and loaded image nodes survive that path.

App restoration uses the existing temporary-room owner when scrolling alone would clamp. Native wheel/touch scroll, layout and clamped-range pixels remain unrun. |
| Hover, swipe or touch on a pending card | No new hover/swipe gesture or pending-card command is introduced. Ordinary links/images retain their existing affordances; native behavior remains unrun. |

The shared formatter fixture now resolves imported names per module, matching
browser lexical imports; it no longer aliases unrelated `cardImages` exports.
The 1233 visual assertion uses formatted words and frozen image identity in
place of the retired preformatted panel/image-count label. Recovery assertions
and existing ten app-consumer failure causes remain unchanged.
