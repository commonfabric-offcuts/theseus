# The gauntlet

Judged changes land on deterministic evidence and an independent read. The
broad gauntlet reports after; a successful Verdict is not a required admission
fact. Warp18843,18852 and18890 supersede the earlier all-or-nothing gate.
[The1131 contract](deterministic-judged-admission-1131.md) gives the exact
judgment fields, evidence bindings and audit obligations.

This describes the1131 policy and source contract, not an installation receipt.
Fable publishes the exact reviewed installed guard path and hashes; Warp
selects the reviewed caller for each landing. A source packet, this guide and
an approval are distinct from installation. Do not assume an older installed
guard or an active historical caller has acquired the new behavior.

## What lands first

- Approved ordinary work lands in every restoration window and never waits
  behind a judged train (Warp18837). Classify the actual frozen diff with
  Core's existing path policy; a deploy-tool change does not become ordinary
  merely because it is small or supports a web feature.
- Judged trains may combine approved frozen sources, with at most three
  Pipeline items (Warp18837 revision1). This replaces the older blanket ban
  on combining judged items. Each member retains its exact source identity,
  approval and named tests; a bundle is not permission to hide a member's red.
- A judged carry is made on actual live after its source approvals. Its
  deterministic evidence names that exact base, head and tree. A later
  landing merge preserves the carry tree and names live and carry as parents.
  The audit explicitly accepts the independently read approval/carry order;
  an authored Git timestamp alone does not establish it.

## What admission reads

The guard reads canonical freezes, approvals and ordinary waiters afresh before
its effects. The1131 judgment binds:

- The whole Node suite on the carry against actual live, retaining each case's
  name, ancestry and multiplicity, all test-file coverage and failing-file
  identities. No added failing case or file is allowed; new passing tests are.
- Passing Core unit tests named for each frozen piece. Under1131 revision3,
  migration-chain files either pass on carry or compare against the same files
  on actual live by case/file identity, with no new failure. Existing migration
  reds remain red. The independent read checks that the named cohort is
  appropriate and complete; a freeze currently has no test inventory of its own.
- A completed real-browser case for each changed web page, with exact source
  and raw record bindings. The reviewer checks the page mapping and actual
  browser/native attribution. A broad browser suite's completeness is not a
  successful-Verdict requirement.
- An affirmative audit decision for the exact evidence digest, including its
  separate approval-before-carry obligation. A rejection or quoted marker is
  not evidence acceptance. Raw outputs, direct exits, captured input snapshots,
  run/attempt identities, counts and material limitations remain available.

A demonstrated deterministic new Python or Node red still refuses. Browser
fixture deaths, modes that never reach their end, body/log inconsistency and
unavailable judge machinery remain attributed failures, not passing cases and
not an independent Verdict veto. Do not manufacture another candidate or feed
the same tree through the gate again merely to repair those machine failures.
Record and fix the machinery separately.

An incomplete run gets a named diagnosis and at most one bounded corrective
attempt. Preserve completed evidence; do not restart a whole suite for a
missing file or repeat a browser retry.

When a change lacks its minimum evidence, name that exact gap and use valid
retained evidence or a specifically authorized alternative. Never invent a
pass, waive a real new failure, or hold unrelated work for that gap.

If live changes, an old base comparison is not current-live evidence. Preserve
what actually ran and prepare the required deterministic evidence for the
actual carry/base; do not relabel a retained run, custom entry script or dirty
snapshot. This does not reinstate a mandatory broad browser gauntlet replay.

## What keeps running

Producers continue on pushes and after landings on release/live73. They report
what they observe, including optional Verdict checks; the auditor's morning read
reports dead browser modes (1129). A cancelled producer establishes incomplete
coverage, not its cause. Inspect the actual caller and cancellation receipt
before attributing a machine defect or product regression, and read the current
shipping record before acting on a notice that says a piece lands next.

The1131 caller proposals remove the historical post-merge producer-cancellation
loop and skip-CI subject. Until the reviewed caller is selected, those are
proposals, not claims about installed behavior. Never deliberately cancel a
producer or skip its push merely because admission no longer waits on Verdict.

Fable owns reviewed guard installation and pipeline transitions; Warp owns
application landing and caller selection. Keep one source owner for shared
deploy-tool edits and name the exact reviewed guard/caller in the release
account. Runtime boundaries and test slots follow the current owned routing;
this guide grants neither a workload nor an installation.
