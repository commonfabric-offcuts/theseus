# A change elsewhere leaves the open page quiet (1229)

One bounded page change window owns background invalidation. It batches the
existing canonical actor/topic/workspace change scopes in one read/snapshot,
retaining each exact cursor, access check and continuation. No subscription,
cache or cursor grants authority. Every scope must succeed; a failed resource
retains dirty work and its original frontier for retry. Hidden pages catch up;
reconnect/resync and binding/access loss keep their current owners.

The changes batch may project canonical rows/counts only for topic identities
actually changed in its authorized workspace scopes. It reuses Core's existing
topic/count owners, with bounded IDs and byte limits. It does not reconstruct
history or scan unrelated records. Browser publication touches only changed
rows, preserving order, hover, focus, New/waiting and Build-topic semantics.

The open topic consumes its topic keys; private actor keys retain whispers,
marks, revisions, reactions, waiting and kept-writing behavior. Other-topic
arrivals never trigger open-topic/tools/memory/pipeline/links/health reads.
Attention follows addressed/private keys. Dimming consumes the same actor
window. Health uses its existing commit facts; release observation follows a
changed release hint or the explicit initial/reconnect owner, not every post.

Feed anchor ownership can be invalidated by an outside layout mutation without
recapturing feed geometry. Only feed mutations, actual feed size changes and
user navigation/scroll paths capture feed anchors. Stable rail rows receive no
DOM write; new/removed/structurally moved rows preserve existing list owners.

Acceptance: commit N identified unrelated messages, positively observe the
correct rail counts, then drain all refreshes. Unaddressed and addressed
variants count every view name/argument and per-change multiplicity; at most3
view reads per message, no unrelated feed/side-panel read, no feed anchor scan,
and no replacement/mutation of unchanged rows. Record layouts, style recalcs,
CPU, source, fixture size and limits. Open arrivals/whispers/writing/scroll,
hover/key/touch/focus, hidden catch-up, retry and authority fences remain.
A mutation restoring broad invalidation/settle must fail the check, with its
restored control. Measurements use owned Chrome-for-Testing on scratch data,
Browser.close and verified terminal/cleanup. Flex owns native instrumentation;
Core7 owns product/contract/unit proof. Trend output becomes a deploy artifact.

An owned read deadline that aborts a pending JSON body after HTTP200 remains a
transport retry. A genuine malformed200 remains diagnostic. Cleanup retains
its actual body/transport occupancy and epoch fence until settlement; command
and upload uncertainty preserves the exact original operation, without resend.
Transient side-rail/star/peek failures retain last-good truth, avoid warning
flicker and have a later retry owner. Typed authority/access/session failures
keep precedence, including when Cleanup defers a read with a typed cause.

The release-specific producer is the unstarted1139 follow-on, not installed1135.
1229 preserves the optional release payload and observed-once consumer on
initial/reconnect observation, plus an explicit future releaseChanged door.
It does not implement that producer or claim release signals exist today.

The tab's unread total remains current for ordinary subscription deliveries.
A private delivery/read change may include only canonical unread/addressed
totals from the existing reader-count owner in the same snapshot, without
loading attention items or raising a notification. Named arrivals still read
the full attention owner once, and a refused attention read remains owed.
A full reconnect/resync obligation survives transient failure with no new key.

Count projections and full attention answers name their snapshot commit.
An older count answer cannot overwrite a later full attention result.
