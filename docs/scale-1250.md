# First topic scale check (1250)

This first ordinary slice supplies verified disposable 100/30000-message seeds,
300 workspace dossiers on both sides, and a warm before/30 topic_messages
measurement through the actual Api decoder and checked envelope. Source and
fixture correctness checks run in the ordinary Core and Node files.

Run `python3 -I tools/scale_1250.py run --out NEW_ABSOLUTE_DIR` through the
installed lane lock. It constructs seeds using actual public commands; only
fixture construction batches commits through savepoints. A separate unbatched
public-command control must match its authoritative shape. An independent full
message/source ledger, summaries, delivery counters, linked rows, integrity and
30-row frontier are verified. No measured read uses the construction adapter.
`seed`, `verify` and `diagnose` expose the same retained fixture/check paths.

The first measurement has nine alternating small/large paired blocks after
exactly two retained excluded warmups per side. The ratio of large/small
sample medians must be <=1.5. Every raw sample, paired ratio, tail, maximum,
refusal and failed setup is retained; no timing floor, deleted outlier or
automatic rerun changes the estimator. End request latency after full body
parse, negotiated root-table expansion and checked message-page identity.
Instrumented full-view SQL/VM diagnostics are separate from primary timing.
OS cache is uncontrolled. Expanded JSON bytes are not network wire bytes.

Other views/shapes, fresh-process/clone cold strata, complete action inventory
and full-history canonical/DOM/native retention remain explicit successor work
under adopted25952; this warm first-view result does not claim that full gate.
The original ten-path plan and forecasts remain retained. A measured red is
reported as red and its demonstrated SQL/summary cause routes to1251; a usable
measuring tool is distinct from a passing live bound. No production owner,
check/release/landing tool, schema or permission policy changes in this slice.
