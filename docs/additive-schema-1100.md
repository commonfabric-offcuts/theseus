# Additive schema classification (1100)

A qualified additive schema step defaults to ordinary after this judged policy
ships and its complete immutable tool source is published. Its version change
still selects the existing `tools/deploy.py` restart recipe: stop, backup,
migrate, restart server/runner, verify, record release.1100 changes
classification and its actual callers; deployment/runtime/guard installation
and the current recipe are unchanged.

## Qualification

`aim_next/judgment.py` reads actual base/head Git blobs, with no worktree,
symlink, import, eval or candidate-test execution fallback. The migration
engine and all existing steps/declarations must remain unchanged. A new step
must append an adjacent version, end at the new literal `SCHEMA_VERSION`, and
contain only supported additions with matching down operations:

- A new table, with an occupied guard covering every row before it can be
  dropped on down. Indexes of that table disappear with its table.
- A nullable or constant-defaulted column, with down dropping only that
  column and occupied checking for values different from its initial default.
  `NOT NULL` requires a non-null default.
- A non-unique index, with its matching drop. An index-only downgrade remains
  safe on populated tables and uses `SELECT 0` for occupied.

Multiple guarded record additions combine their occupied predicates with OR.
Down runs the inverses in reverse order. Old literal SQL imports are compared
transitively. Existing generated declarations/callable backfills are retained
by their entire owner fingerprint rather than executed. A changed old SQL
owner, deletion, unreadable blob or symlink stays judged even if the diff does
not include `migrations.py`. A version change without a qualifying appended
step also stays judged.

Imported SQL owners must be declarative in their entirety, including unused
bindings and imports. Expressions, conditionals, mutations, executable/defaulted
definitions, rebinding, external imports and unsupported assignments cannot
qualify by presenting a safe selected constant. Unchanged historical executable
owners retain both their selected transitive values and a whole-owner hash;
changing either stays judged. The classifier never imports candidate code.

Migration source coverage requires executable test changes calling the real
migration entry for the new/prior versions, assertions, and occupied-loss
refusal checks for record-bearing additions. It does not infer coverage from
a test filename or method label. This bounded source check is not a passing
suite claim: ordinary review/check evidence must still record actual up,
down and occupied executions. The classifier does not execute arbitrary
candidate Python or test code.

Drops, renames, updates/data rewrites, changed old checks/constraints or engine
behavior remain judged. All other deploy/check/controller guarded inputs
remain guarded. Unsupported declaration/test forms, computed defaults,
additional column constraints, unique indexes and triggers do not receive the
exception. These conservative limits name the supported default rather than
claiming general Python/SQL equivalence or arbitrary test semantics.

## Freeze, train and admission

`source_diff` remains a list for existing consumers and JSON, with an optional
immutable `migration_sources` witness from the binder. A source witness names
base/head, the exact changed path list, and bounded before/after input bytes
(or an explicit missing input). Identical head inputs reference their same
base path once, keeping the witness below the existing transport limit.
Oversized/incomplete declaration slices keep judgment. `pipeline.freeze` accepts that optional field
from the already-authorized builder/coordinator/owner. Core derives the mark
with the same pure source policy; a caller cannot supply an ordinary bit.
Foreign/malformed source binding refuses. Missing exception evidence retains
the conservative migration route.

Git reads and candidate suites stay outside Core's transaction. The immutable
command receipt retains the derived migration plan, source identities and
input SHA256 map; existing append-only freeze storage and read shape need no
schema migration. As before, the authorized binder attests actual Git source;
Core itself does not authenticate a Git repository inside a transaction.

Train and admission independently reread immutable Git source at their effect
boundaries. Pending freeze paths bind lazily only when their existing
validator classifies that pending piece; unrelated/unapproved rows cause no
Git work. Their list/JSON shape and the existing validation expression remain
intact, including for1087's extracted freeze validator. Older judged records
stay conservative. Ordinary source mismatches, unavailable commits and
forged file lists refuse. Existing ordinary blockers, scoped pipeline reads,
producer/Verdict authentication and1087 approval/combine behavior are retained.
