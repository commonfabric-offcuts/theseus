# Cover updates keep the current reading position (1276)

Normal cover writes continue. A cover revision updates its existing sheet in the
same dossier/viewer context. Unchanged content rows keep their actual nodes;
changed rows show the new Core words. The sheet remains the reading anchor so
restoration cannot mistake a routine revision for removal and put a following
message at the old cover top. Unchanged text ranges, selection and focused
controls remain connected. Changed words invalidate their old character range.

Context changes and genuine cover removal retire the old sheet. Existing
message-removal/successor fallback, explicit navigation, writing, access,
window disposal and temporary-room policy retain their owners. No new anchor
policy, cover-write suppression or native producer is introduced.

The focused fixture executes the real stack/cover renderer together with the
actual app capture/restore code in a geometry model. It covers same-height
replacement, growth/shrink above/below/crossing the reading point, unchanged
range/selection identity, focused writing, removal and stale/navigation fences.
Old-code red, candidate green and an applied replacement mutant are retained.
Models are not native acceptance. Flex exact446 supplies independent native
RCA: a same-height visible rewrite moves the same connected reply by85px through
restoreListAnchor; the internal saved/fallback objects are source-inferred.
Actual-current carry/read/freeze and subsequent native acceptance stay separate.
